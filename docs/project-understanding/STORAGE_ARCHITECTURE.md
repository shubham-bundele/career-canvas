# CareerCanvas Storage Architecture

## IndexedDB
- **Database Name**: `careercanvas-db`
- **Version**: 1
- **Singleton**: `database` instance from `src/js/core/db.js`

## Object Stores
| Store Name | Key Path | Indexes | Purpose |
|-----------|----------|---------|---------|
| `documents` | `id` | type, lastModified, tags (multi), pinned, archived, targetRole | All document types (resume, CV, cover letter, reference sheet) |
| `masterProfile` | `id` | type, lastModified | Career profile data |
| `jobDescriptions` | `id` | company, role, lastModified, tags (multi) | Job descriptions (ALREADY EXISTS) |
| `applications` | `id` | company, role, status, appliedDate, lastModified | Job applications |
| `contentLibrary` | `id` | type, category, tags (multi), lastModified | Reusable content blocks |
| `snapshots` | `id` | documentId, createdAt | Document snapshots |
| `images` | `id` | type, lastModified | Stored images |
| `designPresets` | `id` | name, category | Design presets |

## CRUD API
```js
database.create(storeName, data)   // Add (fails if exists)
database.read(storeName, id)       // Get by ID
database.update(storeName, data)   // Put (upsert)
database.delete(storeName, id)     // Delete by ID
database.getAll(storeName)         // Get all records
database.getByIndex(storeName, indexName, value)  // Index query
database.query(storeName, filterFn)  // Filter with function
database.count(storeName)          // Count records
database.put(storeName, data)      // Alias for update
database.get(storeName, id)        // Alias for read
```

## localStorage Usage
| Key | Purpose |
|-----|---------|
| `onboardingComplete` | Boolean flag for first-run wizard |
| `cc_theme` | Theme preference ('light' or 'dark') |
| `userSettings` | User settings JSON (name, preferences) |

## Important Notes
- The `jobDescriptions` store ALREADY EXISTS in the database schema
- It has indexes for company, role, lastModified, and tags
- The Job Description Matcher can use this existing store
- A new store for `matchAnalyses` will need a DB version bump to v2
- All IDs are UUID v4 generated by `generateUUID()` from `utils/id.js`
